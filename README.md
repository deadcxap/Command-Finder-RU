# Command Finder RU — поиск команд в терминале

`cf` подбирает консольные команды по описанию задачи на русском или английском языке. Модель работает локально на CPU. В Bash описание задачи в строке ввода можно заменить выбранной командой нажатием `Ctrl+F`, затем проверить, изменить и выполнить её.

```bash
cf "найди большие файлы в текущем каталоге"
cf --print "покажи изменения в git"
cf --copy "сожми папку в tar.gz"
```

В словаре **392 команды и 3 892 русские формулировки в 15 категориях**. Команды заданы в JSON, модель ищет подходящие по смыслу описания. Генерация команд и облачный API для поиска не нужны.

Рабочая модель — [`sergeyzh/rubert-mini-retriever`](https://huggingface.co/sergeyzh/rubert-mini-retriever), 312 измерений, ONNX с 8-битным квантованием. Файл модели занимает около 27 МБ. Во время поиска используются ONNX Runtime и Tokenizers. Готовая модель и поисковая база доставляются из релиза; PyTorch нужен только для подготовки нового артефакта разработчиком или в CI.

## Установка

Автоматический установщик поддерживает Linux и WSL2 на **x86_64**, Python **3.12 или 3.13**. Для горячей клавиши нужен интерактивный Bash 4+ с GNU Readline.

**Зависимости — установите перед установкой проекта** (Debian/Ubuntu, Python 3.12):

```bash
sudo apt-get install python3.12 python3.12-venv bash curl
```

Для Python 3.13 используйте пакеты `python3.13` и `python3.13-venv`.

Установка проекта:

```bash
curl -fsSL https://github.com/deadcxap/Command-Finder-RU/releases/latest/download/install.sh | bash -s -- --shell && source ~/.bashrc
```

Установщик скачивает последний стабильный релиз, проверяет контрольные суммы, создаёт пользовательское Python-окружение и устанавливает готовый wheel приложения. Зависимости берутся с PyPI только в виде готовых wheels, без компиляции. Готовые модель и SQLite-индекс загружаются из того же GitHub Release. Клонировать репозиторий, устанавливать PyTorch и кодировать словарь на своём компьютере не требуется. Скачанные установочные файлы удаляются; дальнейший поиск работает без сети.

Команду выполняют в интерактивном Bash: часть `&& source ~/.bashrc` активирует `cf` и Ctrl+F в текущем терминале после успешной установки. Сам установщик работает в дочернем процессе и не может изменить окружение родительской оболочки.

Флаг `--shell` добавляет загрузчик интеграции в `~/.bashrc`; загрузчик также добавляет `~/.local/bin` в `PATH` сессии, если каталога там ещё нет. Без этого флага устанавливается только команда `cf`. Другое расположение файла оболочки можно задать через `CF_BASHRC`; тогда вместо `~/.bashrc` загрузите этот файл. В конце установщик выводит точную команду активации. При установке без интеграции, если `~/.local/bin` отсутствует в `PATH`, добавьте в `.bashrc`:

```bash
export PATH="$HOME/.local/bin:$PATH"
```

Для выбора Python передайте переменную именно процессу установщика:

```bash
curl -fsSL https://github.com/deadcxap/Command-Finder-RU/releases/latest/download/install.sh | CF_PYTHON=python3.12 bash -s -- --shell && source ~/.bashrc
```

### Конкретная версия и предварительные выпуски

Обычная установка выбирает стабильный релиз. Для конкретной версии, включая RC, используйте `--version`:

```bash
curl -fsSL https://github.com/deadcxap/Command-Finder-RU/releases/download/v0.3.0-rc.1/install.sh | bash -s -- --version v0.3.0-rc.1 --shell && source ~/.bashrc
```

Пример показывает синтаксис выбора версии: указанный тег должен быть опубликован в Releases.

### Обновление и удаление

Для обновления повторите команду установки. Новый выпуск получает собственное окружение и готовую базу; неизменившаяся модель используется повторно. Установщик переключает активную версию только после проверки новой установки. Исходный checkout проекта для запуска не нужен.

Файлы установки располагаются в `~/.local/share/cf-ru`; другой корневой каталог можно выбрать через `CF_INSTALL_DIR`. Это выделенный каталог установки: при первом запуске он должен быть пустым или отсутствовать. Уже управляемый установщиком каталог подходит для обновлений. Команда `~/.local/bin/cf` ссылается на загрузчик в этом каталоге.

При переходе со старой установки из checkout сначала удалите её прежним `uninstall.sh` или вручную освободите ссылку `~/.local/bin/cf` и удалите старое окружение. Сохранённые старые данные оставьте отдельно либо выберите новый пустой `CF_INSTALL_DIR`.

```bash
bash ~/.local/share/cf-ru/uninstall.sh          # удалить приложение и интеграцию, сохранить модель и базы
bash ~/.local/share/cf-ru/uninstall.sh --purge  # также удалить данные этой установки
```

Для нестандартного `CF_INSTALL_DIR` запускайте `uninstall.sh` из выбранного каталога. Пользовательские каталоги, заданные через `CF_DB_DIR` или `CF_MODEL_DIR`, удаляются вручную.

Готовый индекс уже соответствует словарю релиза. После изменения собственного словаря обновите его отдельно: `cf --seed --force`.

### Установка из исходников для разработки

В checkout репозитория создайте отдельное окружение и установите пакет в editable-режиме:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/cf --prepare-model --model-source /home/user/models/rubert-mini-retriever-int8
.venv/bin/cf --seed
source .venv/bin/activate
```

В примере импортируется готовый локальный ONNX-артефакт с `model.onnx`, `tokenizer.json` и `metadata.json` рабочей модели. Можно использовать каталог на месте, задав `CF_MODEL_DIR`. Подготовка модели с нуля требует отдельных тяжёлых зависимостей экспорта и описана в [архитектуре](docs/architecture.md#модель-и-артефакт).

## Использование

```bash
cf "покажи процессы, которые слушают порт"
cf --top 15 "найди файлы по имени"
cf --verbose "покажи свободное место на диске"
```

По умолчанию открывается меню выбора, после которого команда печатается в терминал. С подключённой интеграцией Bash обычный вызов `cf "запрос"` также добавляет выбранную команду в историю, если она включена: нажмите `↑`, чтобы вернуть её в строку ввода и отредактировать. Для замены текущей строки сразу после выбора используйте `Ctrl+F`.

| Режим | Действие |
|---|---|
| `cf "запрос"` | Открыть меню выбора |
| `cf --print "запрос"` | Напечатать выбранную команду |
| `cf --copy "запрос"` | Скопировать команду в буфер обмена |
| `cf --tmux "запрос"` | Передать команду в текущую панель tmux |
| `cf --seed` | Создать индекс словаря |
| `cf --seed --force` | Перестроить индекс |
| `cf --prepare-model` | Подготовить рабочую модель |
| `cf --install-shell` | Напечатать скрипт интеграции Bash |
| `cf --help` | Показать полный список параметров |

Для буфера обмена используются `pbcopy` в macOS или `xclip` в Linux; для режима tmux нужен установленный tmux.

### Меню и Ctrl+F

В меню доступны стрелки или `j`/`k`, `Enter` для выбора, `Esc` или `q` для отмены. Пункт «Показать ещё» подгружает дополнительные результаты.

После подключения интеграции Bash:

- На непустой строке `Ctrl+F` ищет по набранному описанию и заменяет строку выбранной командой.
- На пустой строке `Ctrl+F` сначала предлагает ввести запрос.
- После выбора команда остаётся в строке Readline для редактирования; для выполнения нажмите `Enter`.
- При отмене поиска или ошибке исходная строка сохраняется.

Для поиска горячей клавишей набирайте само описание задачи, без `cf` в начале и без нажатия `Enter`:

```text
найди большие файлы в текущем каталоге  ← Ctrl+F
```

Для установки из пакета добавьте в `.bashrc`:

```bash
eval "$(command cf --install-shell)"
```

В checkout репозитория доступен тонкий загрузчик того же скрипта:

```bash
source /home/user/Command-Finder-RU/shell/cf.bash
```

Привязка `Ctrl+F` действует в текущей интерактивной сессии Bash после подключения скрипта. Она заменяет стандартное перемещение курсора на один символ вправо.

Если используете режим vi (`set -o vi`), включайте его до подключения интеграции `cf`.

### Ограничения поиска

Проверяйте выбранную команду перед выполнением. Модель может перепутать близкие операции, отрицания или важный флаг. На тесте запрос «заморозить процесс, не завершать» ставил `kill` выше нужного `kill -STOP`.

Команды с признаком `destructive` помечаются в меню и в интерактивном терминале требуют отдельного подтверждения перед выводом. При перенаправленном stdin выбирается первый результат, интерактивного подтверждения нет. Эта отметка относится к данным словаря и не проверяет смысл запроса. При запросах вне словаря поиск также может предложить неподходящие команды.

## Настройка

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `CF_TOP` | `7` | Число результатов в меню |
| `CF_MAX_TOP` | `50` | Максимальное число результатов |
| `CF_DB_DIR` | `$CF_INSTALL_DIR/current/data` для релизной установки | База и кеш векторов описаний |
| `CF_DB_NAME` | `cf.db` | Имя файла базы |
| `CF_MODEL_DIR` | `$CF_INSTALL_DIR/current/model` для релизной установки | Каталог готового ONNX-артефакта |
| `CF_DATA_DIR` | Словарь из пакета | Каталог JSON с командами |
| `CF_THREADS` | `2` | Число CPU-потоков модели |
| `CF_BATCH_SIZE` | `32` | Размер пакета при индексации |

Загрузчик релизной установки задаёт стандартные пути базы и модели, сохраняя явно заданные `CF_DB_DIR` и `CF_MODEL_DIR`. Без загрузчика, например при запуске из исходников, стандартный каталог базы — `~/.local/share/cf-ru`, модели — `$CF_DB_DIR/onnx`. `CF_INSTALL_DIR` выбирает каталог во время установки; его значение по умолчанию — `~/.local/share/cf-ru`.

Для одного запуска число результатов можно изменить флагом `--top`. Расширенные настройки модели описаны в [архитектуре](docs/architecture.md).

## Проверки и сравнение моделей

```bash
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m pytest
```

Выбор mini-retriever основан на сравнении 23 конфигураций на 90 задачах для каждого из двух языков. Рабочий 8-битный вариант получил Hit@3 **81,1% для русского и 82,2% для английского**. На тестовой WSL-системе медиана русского поиска после загрузки составила около **9 мс**, пик памяти процесса — **125 МиБ**.

## Происхождение и лицензии

Проект основан на [Command Finder Стивена Коха](https://github.com/stvkoch/Command-Finder). Сохранены схема поиска по словарю, SQLite/sqlite-vec, пакетная индексация, меню выбора и интеграция оболочки. В этой версии добавлены русские формулировки, исправления команд и локальная квантованная модель mini-retriever.

Код распространяется по [лицензии MIT](LICENSE). Модель `sergeyzh/rubert-mini-retriever` также опубликована автором под MIT; её происхождение и закреплённая ревизия указаны в метаданных модели. Веса модели, базы данных и локальные окружения не входят в Git-репозиторий.
